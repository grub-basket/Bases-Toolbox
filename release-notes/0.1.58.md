Five releases' worth of changes, focused on base management and on making recurring CSV imports and duplicate cleanup far less manual.

## 0.1.58

### CSV importer
- **Row picker** — choose exactly which rows import. A collapsible, searchable list shows every parsed row with a chip describing what the import will do to it against the target folder (`new`, `exists → update`, overwrite, skipped, or a `-2` copy, per the collision policy). All / None / Invert act on the *filtered* rows, so slicing like "filter to one provider → None → clear filter" works. Deselected rows are reported separately from policy-skipped ones, and the selection is part of the crash-recovery draft. Any change to the pasted text resets the selection — row indices only mean anything against the exact data they were picked on.
- **Presets** — save the whole importer setup (target folder, column mapping with names/types/included columns/filename column, collision and conflict policies, body template, base options) under a name, and reapply it with one pick. Column settings and the filename column match **by header**, not position, so a re-exported sheet whose column order changed still lines up. Picking a preset before pasting queues it; the mapping applies at first parse. Drift between the preset and the sheet (saved columns missing, new columns present) is called out when the preset applies.
- **Update-mode conflict policy** — when re-importing onto existing notes, choose which side wins for a property that already holds a different value: **imported wins** (previous behavior, still the default) or **keep existing — only fill empty**, so hand-corrected fields survive the next re-import. Overridable **per column** in the mapping table. Blank cells still never clear values, note bodies are never touched, and updates stay revertible from the bulk file change history.

### Duplicate finder
- **Body diffs** — once a note is picked to keep, each differing group member gets a collapsible line diff against it: changed lines highlighted, unchanged runs folded to two lines of context. Bodies over 800 lines are declined politely rather than diffed slowly.
- **Partial merges** — every note in a group has a merge tick; untick one and it's left alone while the rest merge. The merge button and preview follow the selection, and the button disables when nothing is ticked.
- **Merge all visible groups** — with a keep-policy set (oldest / newest / longest), one button merges every group on screen with a progress notice, then rescans. Each group is its own history entry, so any single group can still be reverted. A note sitting in two groups at once is handled safely: members already merged away are skipped, and a group left with fewer than two live notes is passed over.
- **Calmer layout** — all scan controls now live in one collapsible "Scan options" block that folds automatically after a scan. Each member row shows size, property count, and created/edited dates, so picking the keeper doesn't require opening notes.
- Folder include/exclude scoping was re-verified end to end (exclude wins over include).

## 0.1.57
- **Always-skip file extensions** — a settings list (seeded with `edtz`) plus the command **"Exclude skipped file extensions from this base"**, which appends `file.ext != "…"` clauses to the base's top-level filter so those files stop appearing in **every view**. Idempotent (re-running never duplicates a clause), and a base whose top-level filter is an `or` gets wrapped in an `and` so the exclusion actually holds. Revertible from history. Also on the launcher.
- Reverting a base view or column change now reports what it actually reverted ("Reverted: Hid column …") instead of describing it as a note merge.

## 0.1.56
- **Open Stashpad notes in Stashpad** (setting, off by default) — clicking a note in a base that lives in a Stashpad folder opens it in the Stashpad plugin's view, keeping its tree context, instead of the markdown editor. Cmd/Ctrl-click and middle-click open it in a new tab, still in Stashpad. Only notes carrying a Stashpad `id` are redirected — author files, attachments, encrypted files, and everything outside a Stashpad folder open exactly as before. Requires the Stashpad plugin; without it the setting says so once and does nothing.

## 0.1.55
- **"New grid" launcher entry + command** — opens an editable, Excel-style grid over a folder via the separate GridSense plugin. If GridSense isn't installed, is disabled, or has renamed its command, a specific message says which of those it is and what to do — the button never silently does nothing. Bases Toolbox does not otherwise depend on GridSense.

## 0.1.54
- **Columns manager** — a new dialog (toolbar button next to the view switcher, command "Manage columns for this base", launcher entry) for a base view's columns: hide, reveal, reorder (move left/right/front), and **jump to a column** that's scrolled off-screen. The reveal list is built from the properties the base's notes *actually use* — including ones that have never been a column — plus the base's formulas and other views' columns. **Group** re-sorts so note properties lead instead of Obsidian's file attributes (`file.name` stays first). Columns are per-view; a dropdown picks which view when a base has several.
  - Jump-to-column works against the view's real column list rather than the rendered headers (Bases virtualises columns horizontally, so on-screen headers are a sliding window), and scrolls in one step because an animated scroll gets cancelled by Bases' own re-rendering mid-flight.
  - A view with no explicit column list gets one written on the first change here (Bases' defaults are materialised from the live view); this is announced once, and undoing that first change removes the list again.
- Column changes undo **surgically**: reverting restores that one view's `order` against the file as it is now — refusing if the order changed again since — and removes the `order` key entirely when the change was the one that created it.

---

Every change above is revertible from the bulk file change history. Full commit-level details are in the repository history.
