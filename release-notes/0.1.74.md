## Highlights

- **"Export active base results as CSV" fills in formula columns.** Formulas, backlinks, links and the other computed columns come out as the table shows them. They used to be blank, along with file columns such as folder, size and dates.
- **Sync formula writes dates and links correctly.** A date formula used to be written into notes as `true`. Dates are now written as dates, a link stays a link, and a formula that fails for a note leaves that note's property empty instead of writing the error message.
- **The README covers every tool**, and has a step-by-step guide to exporting your tables before you lose access to Obsidian.

## All changes

### 0.1.74

#### Fixes
- `exportBaseCsv` reads `formula.*` and computed `file.*` columns (backlinks, links, embeds, properties) from the base's live results through each entry's `getValue`. Other `file.*` columns (folder, extension, size, created, modified, tags) use `resolveBaseCell`, the same helper as the From a base tab.
- A bare `file` column exports the note's name, which matches what Bases shows for it.
- The done notice says so when Obsidian's results don't expose values, which would mean its internals changed.
- `toPrimitive` in `src/formula-value.ts`, shared by the export and Sync formula into property:
  - Dates give their date string. They used to give the flag that says whether the date has a time, so Sync formula wrote `true`.
  - Links give `[[target]]`, so a synced link stays a link. It used to be written as plain text.
  - File values, from `file()` or `this.file`, give `[[path]]`.
  - Lists give their items.
  - The empty value gives nothing instead of the text "null".
  - A formula that errors for a note gives nothing instead of its error message.
- New `readEntryValue` reads any column of a results entry. `readFormulaValue` uses it.
