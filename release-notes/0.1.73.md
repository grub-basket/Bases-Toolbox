## Highlights

- **Cell colours appear as soon as you scroll a column into view.** A rule that colours one cell used to wait for the table's next refresh when its column was scrolled in sideways.
- **Conditional formatting works in canvas cards and hover popovers.** Tables with no file column are coloured there now, and "is duplicated" rules and rules limited to specific bases work in both places.
- **Old colours no longer come back after you change a rule.** Obsidian reuses table rows and cells it has scrolled away, and one could return still showing the colour from a rule you had since changed or deleted.

Follow-up to [issue #3](https://github.com/grub-basket/Bases-Toolbox/issues/3).

## All changes

### 0.1.73

#### Fixes
- `installConditionalFormatting` handles a `.bases-td` added to an existing row, so a cell-scoped rule colours a column as soon as it appears. Added rows are collected per batch and decorated once.
- With an "is duplicated" rule, new cells use a debounce that doesn't reset, so colours keep up during a continuous scroll.
- A re-added row or cell that still carries a colour marker is cleaned, even when no rules remain.
- `fileForBaseRow` finds rows in canvas cards and hover popovers. The component search also follows `hoverPopover`, `previewMode`, `editMode`, a canvas card's `child` and `canvas.nodes`.
- New `trackHoverParents` remembers the last five objects that opened a popover through the `hover-link` event. Search results, backlinks, tab headers and links inside Bases cells hold their popover on objects no workspace leaf leads to.
- New `baseFileForRow` names the exact `.base` file a component shows. `basePathForRow` prefers it over an embed's `src`, which is link text resolved against the active note.
- Each canvas card is judged on its own base, so one card's base can't apply to its neighbour.
- `redecorateAll` groups remaining rows by `.bases-view`, so duplicate counts work in a canvas card showing a `.base` file directly.
