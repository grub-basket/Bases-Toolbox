Importer additions for building values from multiple columns, plus per-folder memory. Also removes a niche option that didn't pan out.

## 0.1.66 — Importer: composites, filename patterns, per-folder memory

- **Composite (concatenated) properties.** Build a property by joining several columns with your own separators — a `{{Last}}, {{First}}` or `{{Code}}-{{Year}}` pattern — written into a new property, or an existing one to override it. Same `{{Column Header}}` placeholder syntax as the body template.
- **Filename pattern.** Optionally name each note from a `{{First}} {{Last}}` pattern instead of a single column (illegal filename characters are stripped). Together with composites, a filename made of two columns no longer needs a spreadsheet pre-pass.
- **Per-folder setup memory.** Every import remembers its whole setup — column mapping, composites, filename pattern, template, and policies — for the destination folder. The next time you target that folder, a one-click "Reuse that setup" appears. It's the automatic companion to named presets, and it's non-destructive: a button, never an auto-overwrite of an import you're mid-way through.

## Removed

- **Hide view types from the picker** (added in 0.1.64) has been removed. The scenario it was meant for — a community plugin registering a Bases view type with the same name as a native one — doesn't actually occur: such plugins register their own separate views rather than Bases view types, so there was no duplicate in Bases' picker to hide. The option was pulled rather than left as dead weight. The kanban "hide empty columns" button and manual card ordering from the same period are unaffected.
