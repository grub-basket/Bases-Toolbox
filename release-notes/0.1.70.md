## 0.1.70: Clearer scope, safer bulk changes

### Launcher
- **Grouped by what each tool acts on** instead of by how it opens. The sections are **This base**, **One note**, **Explore & review**, **Import & export**, **Many notes at once**, and **Settings**. The tools that rewrite notes across the vault or a folder (Find & replace, Convert / fork a property, Migrate inline fields, Stamp file metadata, Create companion notes) now sit together at the bottom, under a hint that every change is logged and can be undone from History. Each section has a one-line hint. How a tool opens is still shown by its buttons (Sidebar / Tab / Window, or Open).
- **A scope tag on every card**, with a tooltip. The tags are **Whole vault** (orange), **Open base** (accent), **One note** / **Two notes**, **Folder or vault**, **Creates notes**, and **Changes no notes**. The tags are searchable, so typing "vault" lists every vault-wide tool. Tags show in Favorites and search results too, where section headers aren't visible.
- Existing Favorites keep working; their stored ids are unchanged.
- The intro line explains the tags.

### Find & replace vs Bulk edit
- The Find & replace card no longer reads "Bulk-edit a property's values". It says it changes one property's values **in every note in the vault**. The Bulk edit card says it edits **only the open base's filtered rows**.
- The command "Bulk edit properties of base results" is renamed **Bulk edit base results**, matching the launcher and README. The command id is unchanged, so hotkeys keep working.
- The in-app Reference entries for both commands state their scope and point to each other.

### Find & replace: safer by default
- The **Find** dropdown starts on **"Choose a value…"**. Nothing previews and **Apply** stays disabled until a value, or "All values", is chosen. The same happens after switching property, when opened from the palette or the property index without a value, and when a preset value no longer exists. Previously the view opened on "All values" with an empty replacement, one click away from clearing the property everywhere.
- **"All values" asks first.** It shows "Clear “status” in 42 notes?" for an empty replacement, or "Replace every “status” value in 42 notes?" otherwise. Both name the scope and note that the change can be undone. A specific value still applies directly.
- An orange **Whole vault** banner at the top says the tool changes every note that has the property, not just a base's rows.
- After an all-values run the Find dropdown resets, so the view isn't left ready to run it again.

### Find & replace: optional base scope
- A new **Notes** picker appears when a base is open. It offers **Whole vault** (the default) or **Only rows of “Events” (3 notes)**, listed once per open base tab, with repeat tabs labelled "· tab 1", "· tab 2". The preview, the file count and Apply then cover only that tab's rows, after its filters and search. The banner turns accent-coloured and the confirmation names the base.
- If the picked tab is closed, the choice is kept as "(not open)". Nothing previews or applies, and clicking Apply on a stale preview stops with "isn't open any more — nothing was changed". It never widens to the whole vault.
- Row counts include Markdown notes only; a folder filter also matched the `.base` files themselves.

### Undo on the done notice
- After **Find & replace** or **Bulk edit**, the "updated N files" notice carries an **Undo** button and stays up longer. Undo reverts that exact change, even if another change was logged since. It disables after one click and reports "Already undone." if the change was reverted elsewhere.

### Bulk edit: `{{property}}` references
- In the **Value** box, `{{name}}` is filled in **per note from that note's own properties**. For example, set `Time` to `{{startTime}}` to copy each row's startTime.
- **`{{name:format}}` reformats a date or time** with a moment.js format, e.g. `{{startTime:HH:mm}}`. This is the same convention as the CSV importer's `{{date:FORMAT}}`. Parsing is strict: ISO dates and times, `YYYY-MM-DD HH:mm`, dates, and time-only values like `09:30` are accepted. Text that isn't a date is skipped, never turned into a made-up date.
- References can be mixed with text (`at {{startTime:h:mm a}} ({{kind}})`). In Append / Remove mode, each line is resolved on its own, and a line that references a list contributes all of its items.
- A value that is exactly one reference keeps the source's value and is fitted to the **target's** type the way typed text would be. A number copied into a list property becomes a one-item list, a list copied into a text property becomes its items as text, and a number into a number stays a number.
- Notes where a referenced property is **missing or empty** are skipped and counted in the done notice ("Skipped 3 with no startTime"), so a reference never silently clears a value. "Set only if missing" leaves notes that already have the property alone.
- A tip under the Value box explains the syntax. A **live preview** shows what the first note will get and how many notes will be skipped, updating as you type or change the mode or property. Values without `{{` behave exactly as before.
