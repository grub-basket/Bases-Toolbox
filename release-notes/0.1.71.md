You can now set the order properties appear in inside your notes, across many notes at once. Requested in [issue #2](https://github.com/grub-basket/Bases-Toolbox/issues/2).

## Highlights

- **Reorder properties in notes.** A new command, **Reorder properties in notes**, sets the order of the frontmatter properties in many notes at once, which is the order Obsidian's Properties view shows them in. It is also in the launcher and behind a **Reorder properties…** button in **Manage columns**. Only the order changes: values stay exactly as they are, and nothing extra (no order property) is written into your notes.
- **Choose the notes:** the open base's current view (its filtered rows), the whole base (the base's own filters, ignoring the view's), or every note in the vault.
- **Arrange the list** by dragging or with the arrow buttons. It starts from the view's columns, followed by every other property by how often it's used. Properties left out of the list go after the listed ones, or stay where they are; you choose which.
- **Preview first, undo after.** The dialog says how many notes will change, leaves notes that are already in order alone, and asks first above 200 notes. Undo from the done notice, **Undo last change**, or History.
- **Saved orders** can be exported and imported from settings. The file format is shared with **GridSense 0.26.0**, which can import the same saved-orders export, so an order moves between the two plugins.
- **Heads-up:** Obsidian rewrites the frontmatter when it saves it, so **YAML comments in the reordered notes are dropped**, and quoting or spacing may be tidied.

## All changes

### 0.1.71

#### Reorder properties in notes
- New command **Reorder properties in notes** (`reorder-note-properties`), a launcher card in **This base** tagged **Base or vault**, an entry in the in-app Reference, and a **Reorder properties…** button in the **Manage columns** dialog. That button closes the column manager and opens the new dialog for the same base and view.
- **Notes to reorder** (scope dropdown, each option with its note count):
  - **Current view**: the notes the active view shows, after its filters and search.
  - **Whole base**: every Markdown note the base's own top-level filter matches, ignoring the view's filters. Bases has no public API for this, so the plugin re-runs Bases' own compiled filter on each note. If that isn't available on an Obsidian build, the option is hidden rather than guessed.
  - **Entire vault**: every Markdown note. When no base is open this is the only option, and the dialog says so.
- **The ordered list.** It is seeded from the current view's note-property columns (`file.*` and formula columns are skipped), then every other property found in the chosen notes, most used first. Each row shows its position, its name, and how many of the chosen notes have it.
  - Reorder by dragging the grip, or with up and down buttons. The buttons are real, keyboard-reachable buttons, and focus follows the moved row.
  - Remove a row to stop managing that property. Removed properties appear under **Not in the list**, with a button to add each one back.
  - **Add a property** puts any property, with autocomplete, at the end of the list.
  - Property names match regardless of upper and lower case.
- **Properties not in the list:**
  - **Put them after the listed properties** (the default): listed properties come first in list order, then the rest in their existing order.
  - **Leave them where they are**: other properties keep their positions, and the listed ones are shuffled into the slots the listed ones already used.
  - A note that doesn't have a listed property simply skips it.
  - The default is a new setting, and it can be changed each time.
- **Preview line**: "N of M notes will change". Notes already in the requested order are not written, and **Apply** stays disabled when nothing would change. Above 200 notes, a confirmation names the count first.
- **Writing.** Notes are rewritten through Obsidian's frontmatter API, in batches with a progress notice, pausing between batches so the app stays responsive. The order is recomputed from each file at write time, so a property added since the preview is kept and placed by the same rules.
- Numeric property names such as `2024` always come first inside JavaScript objects and can't be moved. The preview allows for this, so those notes aren't reported as changing on every run.
- A heads-up line in the dialog says that Obsidian rewrites the frontmatter on save: YAML comments are dropped, and quoting or spacing may be tidied.

#### Undo and history
- Each run is one entry in the bulk file change history, labelled **property order**, with one row per note (old order → new order) and a checkbox. Revert all of it, or just the notes you pick. The done notice has an **Undo** button, and **Undo last change** works too.
- A revert only reorders notes that still have exactly the order the run left. A note whose properties were added, removed or reordered since is skipped as **edited since**, unless you tick the force option. A forced revert keeps any properties added since, after the restored ones.
- A note that is skipped is never rewritten, so its comments and formatting are left alone.
- Rows are badged **reverted**, **edited since** or **file missing**. A second revert after a partial one counts the already-restored notes as restored.
- A note that can't be written (for example, locked by sync) is reported as **couldn't be written**. The entry then stays open so the revert can be retried.

#### Saved orders
- In the dialog: **Load** a saved order, **Save as…** (asks before replacing one with the same name), and **Update** or **Delete** the loaded one. A saved order stores its property list and its setting for properties not in the list.
- Widening the scope after loading a saved order doesn't add the wider scope's properties to it. They show under **Not in the list** instead, so **Update** can't grow the saved order by accident.
- New settings section **Property orders**:
  - The default for properties not in the list.
  - Each saved order, with **Rename** and **Delete**.
  - **Export**: copies every saved order to the clipboard and also saves it as a `.json` file at a path you choose, `property-orders.json` by default, with autocomplete. It asks before replacing an existing file, creates missing folders, and rejects paths containing `..`.
  - **Import**: paste an export, or pick a `.json` file in the vault. Orders are merged by name. When a same-named order has different contents, you choose **Replace with imported**, **Keep mine**, or **Cancel import**. Identical orders are counted and left alone, and invalid entries are skipped and counted.
- The export format is `{ "format": "property-orders", "version": 1, "orders": [ { "name", "keys", "unlisted" } ] }`, shared with GridSense 0.26.0. Other formats and versions are rejected with a message saying why.
- Saved orders are checked when settings load: malformed entries are dropped and duplicate names removed.
