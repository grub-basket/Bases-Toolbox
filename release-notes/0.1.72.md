## Highlights

- **Conditional formatting works when a table shows a linked property.** A column holding an internal link, such as `projectId: "[[Project]]"`, placed before the file column stopped rows from being coloured. Rows now always use their own note. Thanks to muuky for the report and the diagnosis in [issue #3](https://github.com/grub-basket/Bases-Toolbox/issues/3).
- **Tables with no file column get conditional formatting too.**
- **Zoom into cell and the allowed-values picker always act on the right note and column.** A link written as a full path could point them at the linked note, and a table scrolled sideways could point them at a different property.

## All changes

### 0.1.72

#### Fixes
- Adds `src/base-row.ts` with `fileForBaseRow`, which finds a row's note from its `file.name` or `file.file` cell. With no such cell rendered, it asks the table view that drew the row. It never falls back to another link in the row.
- `fmForRow` in `src/conditional-format.ts`, `resolveBasesCell` in `src/cell-zoom.ts` and `resolveBasesCellSync` in `src/allowed-values.ts` use it in place of the first `[data-href]` in the row.
- Cell zoom and the allowed-values picker read the column from the cell's own `data-property` instead of its position among rendered cells. Obsidian removes off-screen columns, so position could name the wrong property.
- Cell-scoped conditional formatting finds its cell the same way, through the new `cellForProperty`. A rule whose column is off-screen colours nothing rather than a neighbouring cell.

#### Known limits
- A table with no file column inside a canvas card or hover popover stays uncoloured, because the row's note can't be identified there.
- A cell scrolled sideways into view gets its colour on the next refresh of the table.
